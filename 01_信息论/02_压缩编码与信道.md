# 压缩、编码与信道

## 1. 为什么学习这一章

编码把“需要多少信息”变成了可执行的算法和下界。它是理解通信复杂度、数据流摘要、学习系统的表示瓶颈以及 AI4TCS 中 verifier 反馈成本的共同语言。

## 2. 最小知识树

- prefix-free code、瞬时码和 Kraft 不等式；
- fixed-length 与 variable-length coding；
- Huffman 算法：贪心选择、树结构、平均码长；
- Shannon source coding theorem 的上下界口径；
- binary symmetric channel、mutual information 和 capacity；
- random coding 的存在性证明直觉：随机生成码本 + union bound。

## 3. 必须写清的量

对任意编码实验，记录：

```text
source distribution -> code -> average length -> error event -> decoder -> guarantee
```

不要只报告压缩率。要说明分布是否已知、是否允许 block coding、是否允许错误、码本是否随数据分布变化。

## 4. 实验任务

用 Python 实现一个最小 Huffman encoder/decoder：

1. 输入一个字符频率表；
2. 建树并生成 prefix-free code；
3. 检查所有码字满足前缀无冲突；
4. 报告平均码长、固定长度基线和熵；
5. 对均匀分布、偏斜分布和未知分布各做一次测试。

再写一页说明：为什么“平均码长接近熵”与“任何单个样本都能被压缩”是不同说法。

## 5. AI4Math / AI4TCS 连接

- proof trace、程序候选和搜索轨迹都可以被看成需要传输或存储的对象；
- verifier 反馈越细，搜索得到的信息越多，但通信/计算成本也可能增加；
- 在 learning-augmented streaming 中，预测器相当于 side information，关键问题是准确预测时收益和预测错误时退化之间的关系；
- 通信复杂度 lower bound 可以帮助判断某种 sketch 或 verifier 是否不可能同时满足空间、误差和交互限制。

## 完成标准

能从 Huffman 实验中读出熵、平均码长和分布假设的关系，并能口头解释“随机编码证明存在性”与“构造出一个具体编码”的区别。
