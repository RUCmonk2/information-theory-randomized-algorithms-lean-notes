# 随机算法在 AI4TCS 中的验证接口

> 完整讲解见 [随机算法自学讲义](讲义/随机算法自学讲义.pdf)第 6 章；Freivalds 随机验证器的完整案例见第 2 章。

AI4TCS 的“生成候选 -> verifier -> 搜索反馈”闭环，往往需要随机化来提高探索效率或构造测试，但随机性不能替代正确性证明。

## 1. Verifier 的四层

1. **语法层**：候选程序能否解析、编译、满足接口；
2. **小规模正确性层**：穷举或随机测试是否满足规范；
3. **性能层**：时间、空间、通信量或目标函数；
4. **理论层**：不变量、概率保证、复杂度和跨规模行为。

只有第一层通过时，不能说候选算法有效；只有小规模测试通过时，也不能自动获得一般性保证。

## 2. 随机测试设计

- 用固定 seed 重现失败，用多 seed 估计随机波动；
- 测试集分为训练/搜索、validation、hidden 和 out-of-distribution；
- 对每个失败样例保存最小反例，而不是只保存总分；
- 对随机算法报告置信区间或失败次数，不报告单次最好结果；
- 对候选等价变换做去重，避免搜索只找到同一结构的不同写法。

## 3. 小型闭环练习

选择一个 20-50 行以内的算法接口，例如集合覆盖的贪心策略、图遍历顺序或简单调度：

```text
candidate generator -> parser/compiler -> exhaustive small tests
-> hidden random tests -> objective score -> mutation/search feedback
```

把“正确性分数”和“性能分数”分开，记录第一个失败测试和候选的随机 seed。

## 4. 与 Lean 的衔接

- 小规模穷举和随机测试用于发现反例；
- Lean theorem 用于把关键不变量或最终性质变成 kernel-checked 证明；
- 论文中的经验性搜索结果、程序 evaluator 分数和 Lean 证明分别标注证据等级。

## 完成标准

能解释一个 verifier 为什么可能被 benchmark overfitting，能设计一个隐藏测试集，并能明确哪些结论需要 Lean、SMT、穷举或概率证明。
